# アプリ全体モーションシステム 設計

## 目的

Minimal Keys Studio の静止時の見た目と情報設計は維持したまま、クリック、画面切替、保存完了に一貫した手応えを加える。派手さではなく、操作と結果の因果関係が短い動きで分かる、落ち着いた道具らしさを目指す。

## 参考にする原則

- Linear のように外枠とナビゲーションを安定させ、変化した内容へ注意を導く。
- Apple Human Interface Guidelines に従い、動きは目的を持たせ、短く、操作を待たせず、無効化可能にする。
- Material Design のデスクトップ向け目安に合わせ、通常の遷移を 150〜200ms に収める。

参考資料:

- https://linear.app/now/behind-the-latest-design-refresh
- https://developer.apple.com/design/human-interface-guidelines/motion
- https://m1.material.io/motion/duration-easing.html

## 体験の方針

### 固定フレーム

AppHeader、StudioTabView のナビゲーション、AppFooter は画面切替時に動かさない。画面全体を横へ流さず、内容領域だけを切り替える。これにより、現在位置を見失わず、アプリ全体が落ち着いて見える。

### 画面切替

- Studio のトップレベルタブは、旧内容を素早く薄くしてから、新内容を `opacity: 0 → 1`、`translateY: 4px → 0` で表示する。
- 編集／リアルタイム表示の切替も同じ規則を使う。
- トップレベルタブでは、選択中のタブの位置と幅を測り、既存色の背景ピルを 160ms で移動させる。測定できない初回表示やサイズ変更中は現在位置へ即時配置し、操作を止めない。タブ本体やナビゲーション全体は移動させない。
- 現行画面は同階層の切替が中心なので、内容領域に左右方向を付けない。階層ナビゲーションを将来追加する場合は別途設計する。
- アニメーション完了を待たず、切替直後から新しい画面を操作可能にする。

### クリックの手応え

- ボタン、タブ、候補カード、キーキャップは押下中に `translateY(1px)` と `scale(0.98)` を適用する。
- 影がある要素は押下中だけ影を縮め、物理的に沈んだように見せる。
- 押下は 90ms、復帰は 120ms を基準とする。
- 破棄、初期化、削除などの破壊的操作には、弾みや祝福表現を付けない。

### 選択と確定

- キー割当て候補を選んだ時は、選択した候補と対象キーの外周を 180ms だけ淡く強調する。
- 「現在の設定」表示は値が更新された時だけ 220ms の淡い背景変化を出す。
- 保存、接続、適用が本当に成功した時だけ、アイコンを短時間チェックへ切り替える。
- 成功トーストのチェックは `scale(0.8 → 1)` で 160ms 表示する。紙吹雪、音、画面全体の揺れは使わない。

### モーダルと読み込み

- モーダルは背景をフェードさせ、内容を `opacity: 0 → 1`、`scale(0.98 → 1)` で 200ms 表示する。
- 閉じる時は 140ms とし、開く時より短くする。
- 読み込み完了で内容が現れる時は 160ms のクロスフェードを使う。レイアウト全体を滑らせない。
- 通信待ちの表示は要素の幅を変えず、既存アイコンを固定幅領域内で回転させる。アイコンがないボタンは現行ラベルを維持し、ボタンの最小幅を処理前の幅に固定する。

## モーショントークン

CSS カスタムプロパティとして共通値を一か所に定義する。

| 用途 | 時間 | 動き |
| --- | ---: | --- |
| 押下 | 90ms | `translateY(1px) scale(0.98)` |
| 押下から復帰 | 120ms | 標準イージング |
| 画面・タブ内容の入場 | 160ms | `opacity` と最大 4px の移動 |
| 選択確定 | 180〜220ms | 枠・背景・影のみ |
| モーダル入場 | 200ms | `opacity` と `scale(0.98 → 1)` |
| モーダル退場 | 140ms | 入場より速いフェード |

イージングは、入場に `cubic-bezier(0, 0, 0.2, 1)`、状態変化に `cubic-bezier(0.4, 0, 0.2, 1)` を使う。`transition-all` は増やさず、`transform`、`opacity`、`box-shadow`、`background-color`、`border-color` を明示する。

## 実装構成

新しいアニメーション依存ライブラリは追加しない。`src/index.css` にトークンと共通クラスを置き、React コンポーネントは画面切替、確定、入退場の状態を `data-motion-state` 属性として渡す。押下状態はネイティブ要素の `:active` と React Aria の既存 `data-pressed` を使う。

主な適用先:

- `StudioTabView`: トップレベルタブの背景ピル位置を測定し、内容領域の切替状態を付与
- `KeyboardWorkspace`: 編集／リアルタイム表示の切替
- `Key` と Behavior picker: キーキャップ、候補、割当て確定
- `AppHeader` と各設定画面: 保存、接続、適用ボタン
- 共通 Toast: 成功、エラー、読み上げ
- 既存モーダル: 接続、ロック解除、About、未保存確認

共通クラスは「押せる要素」「内容入場」「確定フィードバック」「モーダル入退場」の責務ごとに分ける。モーダルの退場だけは 140ms 後にアンマウントする小さな共通処理を使う。各画面固有の保存処理や通信処理は変更しない。

## 状態と結果の扱い

CSS は押下、hover、focus など、その場で確定する入力反応を担当する。React は画面切替、選択確定、非同期処理の成功・失敗をCSSへ伝える。

成功演出は既存処理が成功を確定した後にだけ開始する。保存要求を送信した時点では開始しない。失敗時は成功演出を出さず、既存のエラー表示と編集内容の保持を優先する。再試行はアニメーションに依存せず実行できる。

## アクセシビリティ

- `prefers-reduced-motion: reduce` では移動、拡大、バウンドを止め、80ms以下の色・透明度変化だけを残す。
- フォーカスリングはモーション設定に関係なく維持する。
- 成功通知は `role="status"` と `aria-live="polite"`、エラーは `role="alert"` を使う。
- 動きだけで成功、失敗、選択状態を伝えず、既存の文字、色、アイコンも維持する。
- マウス、タッチ、キーボード操作で同じ押下状態が得られるよう、React Aria の `data-pressed` とネイティブの `:active` を使い分ける。

## 検証

### 自動テスト

- タブ切替時に内容のキーと入場状態が更新されること。
- 保存成功時だけ確定状態が発生し、失敗時は発生しないこと。
- Toast の成功・エラーに適切な ARIA 属性が付くこと。
- 既存の保存、接続、割当て、未保存確認の回帰テストが通ること。
- `npm test`、`npm run lint`、`npm run build`、`npm run tauri build` が成功すること。

### 目視確認

- 800×600 と通常のデスクトップ幅で、タブ、モーダル、候補、キーキャップを確認する。
- 連続してキーを割り当てても、光や移動がうるさく感じないことを確認する。
- OS の「視差効果を減らす／動きを減らす」を有効にし、移動が停止して操作性が残ることを確認する。
- 低速な接続と保存失敗を再現し、成功演出が先に出ないことを確認する。

## 対象外

- 静止時の配色、余白、タイポグラフィ、画面構成の全面変更
- 紙吹雪、効果音、常時動く装飾、背景パララックス
- ファームウェア、RPC、保存形式の変更
- 新しいアニメーションライブラリの追加

## 完了条件

アプリ全体の主要な押下要素と画面切替が同じ速度・距離・イージングで動き、保存などの成功結果と演出が一致すること。既存機能、キーボード操作、動きを減らす設定を壊さず、静止画では従来のUIを維持すること。
