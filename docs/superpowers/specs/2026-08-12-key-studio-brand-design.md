# Key Studio ブランド変更設計

**作成日:** 2026-08-12

**対象:** `minimal-keys-studio` の表示名称、アプリアイコン、ブランド表記

**状態:** ユーザー承認済みデザイン

## 1. 目的

現在の「minimal-keys カスタマイズ」を、将来ほかのキーボードにも対応できる独立ブランド **Key Studio** へ変更する。

目指す印象は、静かで精密なプロ向けツールである。Apple製品を思わせる端正さは、ロゴや純正アイコンの模倣ではなく、少ない要素、精密な丸み、十分な余白、アルミとグラファイトの素材感、小サイズでも読める輪郭として取り入れる。

現時点の対応機種はminimal-keysであることを説明文に明記し、名称だけで汎用互換を約束しない。

## 2. 正式名称と言葉

- 正式名称: `Key Studio`
- 日本語での読み: キースタジオ
- 製品説明: プロ向けキーボード設定・モニタリングツール
- 現在の対応表示: `現在はminimal-keysに対応`
- ZMKは主ブランドから外し、About、ライセンス、NOTICE内の技術帰属として残す。
- UIに表示する製品名は、英字の大文字小文字と空白を含めて `Key Studio` に統一する。

`minimal-keys` は、接続対象のハードウェア名と対応機種名として維持する。アプリ名とハードウェア名を混同しない。

## 3. アイコン

### 3.1 採用方向

採用案は **Precision Silver / Control Grid / Active + Status** とする。

- ベースはmacOSの角丸に馴染むシルバーのスクワークル形状。
- 中央に黒い3×3のキーグリッドを置く。
- 中央キーをオレンジにする。
- 右上に小さなティールの状態ランプを置く。
- アイコン内に文字、`K`、`Key Studio`、`minimal-keys`を入れない。
- Appleロゴ、Apple純正アプリ固有の図形、既存商標を模倣しない。

### 3.2 色の役割

- シルバー: 精密さ、道具、プラットフォーム
- グラファイト／黒: プロ向けの落ち着き、キーグリッド
- オレンジ: 操作、カスタマイズ、長押しなどのアクション
- ティール: 接続、正常、準備完了

オレンジとティールは同面積で競わせない。オレンジの中央キーを主アクセント、ティールの状態ランプを副アクセントにする。アプリ内では既存の意味を維持し、オレンジは長押し表示、ティールは接続や主要操作に使う。

### 3.3 アイコン正本と派生物

- 編集可能なベクター正本を `design/brand/key-studio-icon.svg` の1ファイルに集約する。
- 正本は1024×1024のアートボードとし、macOSとmaskable iconの切り抜きでも主要要素が欠けない安全余白を持たせる。
- 正本から1024px PNGを生成する。
- Tauriが必要とするmacOS、Windows用PNG、ICNS、ICOを生成する。
- PWA用192px、512px、maskable 512px、Apple Touch Iconを同じ正本から生成する。
- 16px、32pxでは細部を省略しても、オレンジの中央キーとティールのランプが判別できることを優先する。
- 16pxでも3×3グリッドが単なる黒い塊に見えず、オレンジとティールが隣接して一色に見えないことを合格条件とする。
- ラスター派生物を手作業で個別修正しない。修正は正本へ戻す。

## 4. 変更範囲

### 4.1 表示上変更するもの

- Tauriの製品名とウィンドウタイトル
- macOSのアプリ名、DMG名
- Windowsのインストーラー名と表示名
- アプリヘッダー
- 未接続画面と接続説明
- Webページタイトル、description、PWA manifest
- favicon、アプリアイコン、画面内ブランドロゴ
- READMEの製品概要と、独自製品／ZMK技術帰属の関係
- Tauriのshort description、long descriptionなど空欄の製品説明

### 4.2 互換性のため維持するもの

- Bundle ID: `com.hyhy-masa.minimal-keys-customize`
- 内部実行名: `minimal-keys-customize`
- npm package名: `minimal-keys-studio`
- アプリの設定保存場所
- キーマップ書き出し形式: `minimal-keys-studio-keymap`
- 既存バックアップの読込互換性
- ファームウェア、USB、BLEで報告されるデバイス名 `minimal-keys`
- RPC、proto、Raw HID、Studio接続の契約
- ZMKのライセンス、NOTICE、帰属表示

表示名の変更で既存ユーザーの設定やmacOS上のアプリ同一性を失わないことを優先する。Bundle ID、保存形式、通信契約はブランド変更の対象外とする。

## 5. UI内のブランド構造

- ヘッダーの主名称は `Key Studio`。
- 接続画面は `Key Studio` を主見出しにし、補助文で `現在はminimal-keysに対応` と表示する。
- 接続後に表示される `minimal-keys` は接続中のデバイス名として扱う。
- AboutはKey Studioの説明を先に置き、その後にZMK Studio由来の技術、ライセンス、NOTICEを明示する。
- フッターのZMK Contributors表記は帰属として維持するが、主ブランドのようには見せない。
- 旧ZMK faviconや、現在使われていない旧ロゴは参照を外す。削除は参照状況とライセンス上の保存要否を確認してから行う。

## 6. 移行と失敗時の扱い

- ブランド変更はアプリ内設定を書き換えない。
- 新しいアプリをインストールする前に、Bundle IDと設定保存先が従来と同じであることを確認する。
- インストールの上書きは、ビルドと検証の完了後にユーザーへ実行直前の承認を求める。
- 旧アプリは完全削除せず、復元可能な形でゴミ箱へ移す。
- 新アプリの起動、既存設定読込、実機接続のいずれかに失敗した場合は、旧アプリを戻せる状態を維持する。
- 名称変更後も同一Bundle IDのため、同時に旧名称と新名称のアプリをApplicationsへ残さない。

## 7. 検証

### 7.1 自動検証

- 製品名と主要メタデータが `Key Studio` へ変更されたことをテストする。
- 互換性識別子、書き出し形式、デバイス名、RPC契約が変わっていないことをテストする。
- `npm test`
- `npm run lint`
- `npm run build`
- `npm run build-storybook`
- `npm run tauri build`
- `cargo test --manifest-path src-tauri/Cargo.toml`
- `git diff --check`

### 7.2 視覚検証

- 16px、32px、128px、512px、1024pxでアイコンを確認する。
- 明るいDockと暗いDockで輪郭を確認する。
- macOSのDock、Finder、アプリ切替、起動画面で確認する。
- 800×600と1200×800でヘッダー、接続画面、About、ウィンドウタイトルを確認する。
- オレンジ中央キーとティール状態ランプが小サイズで混ざらないことを確認する。
- 旧名称、旧favicon、不要なZMK主ブランド表記が残っていないか検索と実画面で確認する。

### 7.3 インストール後の実機検証

- インストール済み実行ファイルと検証済みbundleのハッシュが一致する。
- codesign検証が成功する。
- 既存設定が読み込まれる。
- 右手USB、Raw HID、Studio RPCへ接続できる。
- Auto Mouseレイヤー、オレンジ枠、候補スクロール、Transparent、トラックボールスクロールが維持される。
- 保存後にreadbackが一致する。

## 8. 非対象

- ファームウェアのデバイス名変更
- Bundle ID変更
- RPC、proto、ファームウェア機能の変更
- UI全体の配色変更
- Apple Developer ID取得、Apple公証、ストア公開
- 他機種対応そのものの実装
- 外部公開、Webサイト、ドメイン取得

他機種対応は将来の独立タスクとし、今回のブランド変更では名前と説明が将来拡張を妨げない状態までを扱う。

## 9. 公開前ゲート

`Key Studio` の商標、主要アプリストアでの同名製品、ドメイン、公開リポジトリ名の競合は現時点で未調査である。ローカル版の名称変更と検証は進めてよいが、第三者への配布、ストア申請、Webサイト公開の前に、最新情報を一次情報で調査して名称を再承認する。

## 10. 採用しなかった案

- `minimal-keys`を名称に残す案: 現在の機種との結び付きは強いが、将来の他機種対応を妨げるため不採用。
- 分割キーボード形状のアイコン: 既存ブランドの継承には強いが、特定機種専用に見えるため不採用。
- グラファイトを主面にする案: プロ向けの強さはあるが、希望された明るく端正なApple的印象ではPrecision Silverに劣るため不採用。
- ティールまたはオレンジ一色: 既存UIが持つ接続と操作の二つの意味を表現できないため不採用。
- 二色を同面積で使う案: 小サイズで騒がしくなり、プロ向けの静けさを損なうため不採用。
